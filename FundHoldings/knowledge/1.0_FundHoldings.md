## Purpose

A read-only table of Vanguard and F/m Treasury/TIPS fund holdings by CUSIP, enriched with ask/SA/SAO yield, term, and duration, plus fund-level weighted averages — so a fund's actual portfolio composition can be inspected security-by-security rather than trusting the fund's summary stats alone.

---

## Architecture — same shared R2 pipeline as every other app

FundHoldings follows the standard pattern: primary data lives in Cloudflare R2 ([S11](../../knowledge/DATA_DICTIONARY.md#s11)), populated by a scheduled Windows Task, and the browser reads only from R2 — no data is git-committed.

1. **Fetch** ([E7](../../knowledge/DATA_DICTIONARY.md#e7)/[E8](../../knowledge/DATA_DICTIONARY.md#e8)/[E9](../../knowledge/DATA_DICTIONARY.md#e9)/[E10](../../knowledge/DATA_DICTIONARY.md#e10)/[E11](../../knowledge/DATA_DICTIONARY.md#e11)/[E12](../../knowledge/DATA_DICTIONARY.md#e12)): `vanguard/updateVanguardHoldings.js`, `fminvest/updateFminvestHoldings.js`, `pimco/updateLtpzHoldings.js`, `schwab/updateSchpHoldings.js`, `bondbloxx/updateXhlfHoldings.js`, or `ishares/updateIcpiHoldings.js` writes `data/Holdings-<TICKER>.csv` to a local scratch dir (gitignored), then uploads it to R2 under `FundHoldings/` via `shared/upload.js`.
2. **Enrich**: `enrichHoldings.js` reads that raw CSV, cross-references R2 stores [S10](../../knowledge/DATA_DICTIONARY.md#s10) (TIPS: ask/SA/SAO yield) and [S7](../../knowledge/DATA_DICTIONARY.md#s7) (nominals: ask yield, coupon — filtered to non-TIPS rows of the combined `FidelityTreasuriesTips.csv` by the `Product` column) by CUSIP, computes `Term`/`Duration` via `shared/src/bond-math.js`, writes `data/Holdings-<TICKER>-Enriched.csv` locally, and uploads it to R2.
3. **Display**: `index.html` fetches the enriched CSV (and `FundMeta.json`) directly from the public R2 URL, same as every other app's client-side fetch.

**Automation**: `updateAllHoldings.js` runs steps 1–2 for every supported ticker (VBIL/VTIP/VTP via Vanguard, RBIL via fminvest, LTPZ via PIMCO, SCHP via Schwab, XHLF via BondBloxx, ICPI via iShares). Scheduled via Windows Task Scheduler (`FundHoldings`, daily 6:40am PT — registered in `scripts/setup-windows-tasks.ps1`), matching the cadence of the rest of the ingestion pipeline.

Adding a new fund: add its ticker to the `FUNDS` array in `index.html` and to the appropriate ticker list (`VANGUARD_TICKERS`/`FMINVEST_TICKERS`/`PIMCO_TICKERS`/`SCHWAB_TICKERS`/`BONDBLOXX_TICKERS`/`ISHARES_TICKERS`) in `updateAllHoldings.js`.

## Data Sources

| Provider | Script | Funds | Notes |
|---|---|---|---|
| Vanguard Advisors API ([E7](../../knowledge/DATA_DICTIONARY.md#e7)) | `vanguard/updateVanguardHoldings.js` | VBIL, VTIP, VTP | Tries `holdings/daily`, falls back to `holdings/latest` |
| fminvest.com API ([E8](../../knowledge/DATA_DICTIONARY.md#e8)) | `fminvest/updateFminvestHoldings.js` | RBIL | ETF id hardcoded per fund (`FUND_IDS`); coupon/maturity parsed from the holding name suffix |
| PIMCO fund-detail API ([E9](../../knowledge/DATA_DICTIONARY.md#e9)) | `pimco/updateLtpzHoldings.js` | LTPZ | Fund CUSIP hardcoded per fund (`FUND_CUSIPS`); xlsx export parsed via the `xlsx` package; coupon preferentially parsed from the holding description suffix (full precision) rather than the API's rounded `Coupon Rate` column |
| Schwab Asset Management holdings export ([E10](../../knowledge/DATA_DICTIONARY.md#e10)) | `schwab/updateSchpHoldings.js` | SCHP | Requires Puppeteer (headless Chrome) — Schwab's site 403s plain HTTP requests (Akamai bot protection), confirmed by direct testing. The official per-fund holdings CSV has no CUSIP (uses Bloomberg FIGI) and no dollar Market Value (only Quantity + precise % of Assets); the scraper resolves both by matching each holding's (Maturity Date, Coupon) against [S7](../../knowledge/DATA_DICTIONARY.md#s7) (which is CUSIP-keyed and carries price) — see E10 for the derivation |
| BondBloxx product-page holdings table ([E11](../../knowledge/DATA_DICTIONARY.md#e11)) | `bondbloxx/updateXhlfHoldings.js` | XHLF | No JSON/CSV API; the product page server-renders the full holdings table as static HTML, parsed directly (fund URL hardcoded per ticker). No Quantity/Coupon/Maturity Date columns — Coupon and Maturity Date are parsed from the `"US T BILL ZCP MM/DD/YY"` name suffix, same technique as fminvest's name-suffix parsing |
| BlackRock iShares fund-document API ([E12](../../knowledge/DATA_DICTIONARY.md#e12)) | `ishares/updateIcpiHoldings.js` | ICPI | Plain CSV export, keyed by the fund's numeric `portfolioId` (hardcoded per ticker, no public ticker lookup); a preamble (fund name, as-of date) sits above the actual holdings table, so the header row is located by content rather than assumed at line 0. The source reports its own Duration/YTM/Real Duration/Real YTM columns, but these are discarded in favor of `enrichHoldings.js`'s own computation so ICPI's figures stay comparable to every other fund's |

All six scrapers write the same `CSV_HEADERS` shape (`CUSIP, Holding Name, Ticker, Category, Quantity, Coupon, % of Fund, Market Value, Maturity Date, ISIN, SEDOL, As of`) and record fund metadata (`fundName`, provider id) to `FundMeta.json`, uploaded to R2 alongside the holdings CSVs.

**MKTLIQ** (Vanguard) and **SSC GOVERNMENT MM GVMXX** (PIMCO and Schwab share the same State Street sweep vehicle), both cash-sweep vehicles, report a placeholder far-future maturity from their provider; `enrichHoldings.js` treats either as maturing tomorrow so `Term` reads as ~overnight rather than a meaningless multi-year figure.

## Enrichment Logic (`enrichHoldings.js`)

For each holding row, by CUSIP:
- **TIPS match** (found in [S10](../../knowledge/DATA_DICTIONARY.md#s10)): `Ask Yield`, `SA Yield`, `SAO Yield`, `Coupon` come from the S10 row.
- **Nominal match** (found in the non-TIPS rows of [S7](../../knowledge/DATA_DICTIONARY.md#s7)): `Ask Yield` = `Ask yield to maturity / 100`. No SA/SAO (nominals aren't seasonally adjusted).
- **No match** (cash/sweep lines, e.g. "US Dollar", MKTLIQ): `Ask Yield`/`Coupon` stay blank; excluded from weighted averages (see below).

In both match cases, the displayed `Coupon` always comes from the matched S10/S7 row (percent-scale, e.g. `6.75` for a 6.75% coupon — matching the convention every raw per-provider fetcher already writes), overwriting whatever the fund's own raw export reported for that holding. This matters because a provider's own export can round the coupon (e.g. BlackRock/ICPI reports `0.13` for the actual 0.125% coupon on the TIPS); S10/S7 are always full-precision.

CUSIP presence in the TIPS yield source (S10) is the source of truth for "is this a TIPS holding" — more reliable than the holding name text or a per-fund flag, and correctly handles a fund that mixes TIPS and nominal holdings (e.g., a fund holding both TIPS and short-term nominal bills).

`Term` = `termYears(settle, maturity)` (only if maturity is in the future). `Duration` = `calculateDuration(settle, maturity, coupon, askYield)` (only if term, coupon, and ask yield are all available).

## Display (`index.html`)

**Banner**: ticker, fund name, Expense Ratio, 30-Day SEC Yield, holdings count, and as-of date, in that order — any field missing from `FundMeta.json` for a given fund is skipped rather than shown blank. Expense Ratio and SEC Yield are each provider's own reported figure (from `FundMeta.json`, percent-scale), not independently computed — unlike the holdings table's Ask/SA/SAO Yield and Duration, which are always `enrichHoldings.js`'s own cross-fund computation (see Enrichment Logic below).

**Columns** (display order): CUSIP, Holding Name, Maturity Date, Coupon, % of Fund, Market Value, Ask Yield, SA Yield, SAO Yield, Term, Duration. `SA Yield`/`SAO Yield` columns are omitted entirely for funds with no TIPS holdings (e.g., VBIL — all nominal Bills).

**Weighted averages** (footer row): `calcMktWtdAvg` over `Coupon`, `Ask Yield`, `SA Yield`, `SAO Yield`, `Term`, `Duration`, weighted by `Market Value`. Cash/sweep rows (no CUSIP match, so `Ask Yield` is null) are **excluded from the weighted-average population entirely**, not just zero-weighted — a cash line can carry a negative market value (e.g. "US Dollar") that would distort the weighted sum if merely down-weighted.

**Term unit**: displayed in weeks instead of years when every bond-row term is under one year (short-duration funds like VBIL read better as weeks-to-maturity).

**fminvest name cleanup**: fminvest-sourced `Holding Name` values embed the coupon/maturity suffix in the text itself (duplicating the Coupon/Maturity Date columns); this suffix is stripped for display only (a no-op for Vanguard-sourced names, which never carry it).

Tabs (one per ticker in `FUNDS`), column sort (click header, blanks always sort last, persists across tab switches so a sort like Maturity Date carries over when comparing funds), and drag-to-resize column widths (session-only, not persisted) — no server-side state.
