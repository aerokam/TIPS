## Purpose

A read-only table of Vanguard and F/m Treasury/TIPS fund holdings by CUSIP, enriched with ask/SA/SAO yield, term, and duration, plus fund-level weighted averages — so a fund's actual portfolio composition can be inspected security-by-security rather than trusting the fund's summary stats alone.

---

## Architecture — same shared R2 pipeline as every other app

FundHoldings follows the standard pattern: primary data lives in Cloudflare R2 ([S11](../../knowledge/DATA_DICTIONARY.md#s11)), populated by a scheduled Windows Task, and the browser reads only from R2 — no data is git-committed.

1. **Fetch** ([E7](../../knowledge/DATA_DICTIONARY.md#e7)/[E8](../../knowledge/DATA_DICTIONARY.md#e8)): `vanguard/updateVanguardHoldings.js` or `fminvest/updateFminvestHoldings.js` writes `data/Holdings-<TICKER>.csv` to a local scratch dir (gitignored), then uploads it to R2 under `FundHoldings/` via `shared/upload.js`.
2. **Enrich**: `enrichHoldings.js` reads that raw CSV, cross-references R2 stores [S10](../../knowledge/DATA_DICTIONARY.md#s10) (TIPS: ask/SA/SAO yield) and `FidelityTreasuries.csv` (nominals: ask yield, coupon) by CUSIP, computes `Term`/`Duration` via `shared/src/bond-math.js`, writes `data/Holdings-<TICKER>-Enriched.csv` locally, and uploads it to R2.
3. **Display**: `index.html` fetches the enriched CSV (and `FundMeta.json`) directly from the public R2 URL, same as every other app's client-side fetch.

**Automation**: `updateAllHoldings.js` runs steps 1–2 for every supported ticker (VBIL/VTIP/VTP via Vanguard, RBIL via fminvest). Scheduled via Windows Task Scheduler (`FundHoldings`, daily 6:40am PT — registered in `scripts/setup-windows-tasks.ps1`), matching the cadence of the rest of the ingestion pipeline.

Adding a new fund: add its ticker to the `FUNDS` array in `index.html` and to the appropriate ticker list (`VANGUARD_TICKERS`/`FMINVEST_TICKERS`) in `updateAllHoldings.js`.

## Data Sources

| Provider | Script | Funds | Notes |
|---|---|---|---|
| Vanguard Advisors API ([E7](../../knowledge/DATA_DICTIONARY.md#e7)) | `vanguard/updateVanguardHoldings.js` | VBIL, VTIP, VTP | Tries `holdings/daily`, falls back to `holdings/latest` |
| fminvest.com API ([E8](../../knowledge/DATA_DICTIONARY.md#e8)) | `fminvest/updateFminvestHoldings.js` | RBIL | ETF id hardcoded per fund (`FUND_IDS`); coupon/maturity parsed from the holding name suffix |

Both scrapers write the same `CSV_HEADERS` shape (`CUSIP, Holding Name, Ticker, Category, Quantity, Coupon, % of Fund, Market Value, Maturity Date, ISIN, SEDOL, As of`) and record fund metadata (`fundName`, provider id) to `FundMeta.json`, uploaded to R2 alongside the holdings CSVs.

**MKTLIQ** (a cash-sweep vehicle) reports a placeholder far-future maturity from Vanguard; `enrichHoldings.js` treats it as maturing tomorrow so `Term` reads as ~overnight rather than a meaningless multi-decade figure.

## Enrichment Logic (`enrichHoldings.js`)

For each holding row, by CUSIP:
- **TIPS match** (found in [S10](../../knowledge/DATA_DICTIONARY.md#s10)): `Ask Yield`, `SA Yield`, `SAO Yield`, `Coupon` come from the S10 row.
- **Nominal match** (found in `FidelityTreasuries.csv`): `Ask Yield` = `Ask Yield to Maturity / 100`, `Coupon` = `Coupon / 100`. No SA/SAO (nominals aren't seasonally adjusted).
- **No match** (cash/sweep lines, e.g. "US Dollar", MKTLIQ): `Ask Yield`/`Coupon` stay blank; excluded from weighted averages (see below).

CUSIP presence in the TIPS yield source (S10) is the source of truth for "is this a TIPS holding" — more reliable than the holding name text or a per-fund flag, and correctly handles a fund that mixes TIPS and nominal holdings (e.g., a fund holding both TIPS and short-term nominal bills).

`Term` = `termYears(settle, maturity)` (only if maturity is in the future). `Duration` = `calculateDuration(settle, maturity, coupon, askYield)` (only if term, coupon, and ask yield are all available).

## Display (`index.html`)

**Columns** (display order): CUSIP, Holding Name, Maturity Date, Coupon, % of Fund, Market Value, Ask Yield, SA Yield, SAO Yield, Term, Duration. `SA Yield`/`SAO Yield` columns are omitted entirely for funds with no TIPS holdings (e.g., VBIL — all nominal Bills).

**Weighted averages** (footer row): `calcMktWtdAvg` over `Coupon`, `Ask Yield`, `SA Yield`, `SAO Yield`, `Term`, `Duration`, weighted by `Market Value`. Cash/sweep rows (no CUSIP match, so `Ask Yield` is null) are **excluded from the weighted-average population entirely**, not just zero-weighted — a cash line can carry a negative market value (e.g. "US Dollar") that would distort the weighted sum if merely down-weighted.

**Term unit**: displayed in weeks instead of years when every bond-row term is under one year (short-duration funds like VBIL read better as weeks-to-maturity).

**fminvest name cleanup**: fminvest-sourced `Holding Name` values embed the coupon/maturity suffix in the text itself (duplicating the Coupon/Maturity Date columns); this suffix is stripped for display only (a no-op for Vanguard-sourced names, which never carry it).

Tabs (one per ticker in `FUNDS`), column sort (click header, blanks always sort last), and drag-to-resize column widths (session-only, not persisted) — no server-side state.
