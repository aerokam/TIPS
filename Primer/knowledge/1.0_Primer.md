# 1.0 Treasury Securities — A Primer

## Purpose

A slide-deck introduction to marketable Treasury securities — bills, notes,
bonds, and TIPS — for a retail investor who has never read 31 CFR Part 356.
Covers every §356.2 definition and Appendix B formula relevant to holding and
pricing these securities (not to bidding mechanics, coverage ratios, or other
auction-operations trivia). Skips Floating Rate Notes beyond a couple of brief
mentions, and STRIPS beyond its one-paragraph definition (Appendix B §V is out
of scope). Formulas that are individually correct but only matter for edge
cases (short/long first coupon periods, half-payment-period bookkeeping, the
FRN discount-margin formulas) are summarized conceptually rather than derived.

Design language: unlike the SeasonalAdjustments "graphic novel" (one hero SVG
chart per page), this book is definition- and formula-dense, so each page's
`content` div is populated with plain HTML (definition cards, tables, worked
examples) rather than an SVG draw function. The outer chrome — topbar, TOC
drawer, pager, dots — is the same pattern as SeasonalAdjustments, reused
verbatim for visual consistency across the Educational group.

Par/Par amount/Principal/Price (page 1) was deliberately pulled out of its
original chapter and placed right after the intro page, ahead of
Bills/Notes/Bonds (pages 2–4) — those security-type definitions lean on
"par"/"par amount" throughout their own CFR text, but par/price concepts
don't depend on knowing what a bill/note/bond is, so the dependency only
runs one direction.

**Titles and chapters are intentionally blank on pages 0–6** (empty `ch:`/
`title:` fields in that page's `content/deck.md` section) — this is a
standing practice, not a bug: don't assign page titles or chapter categories
until content and page order have actually settled, since premature titles
(and the "we'll explain X shortly" cross-references they invite) go stale
every time content moves, which it still is. The TOC falls back to
`(uncategorized)` / `(untitled)` for blank `ch`/`title` so navigation stays
usable in the meantime (see the `lastCh` chapter-grouping logic in
`index.html` — it's seeded to `null`, not `''`, specifically so a page with
`ch: ''` still opens its own chapter group instead of silently merging into
an uninitialized sentinel). Apply the same blank-until-settled practice to
any new page added while content is still moving; only fill in `ch`/`title`
once the page's place in the deck is actually decided.

**Card convention for pages 0–5** (the only pages revised to this convention
so far — the rest of the deck predates it and is due for the same treatment
eventually): term as heading, then the CFR definition in plain text — no
quote marks, no italics — with its citation linked inline at the end; then a
`Usage:` line quoting the term used elsewhere in the CFR, with the specific
word/phrase underlined (not italicized — italics are reserved for cases
where the CFR itself uses them) and its own citation linked; then a `Notes:`
line, populated only when the user has dictated content for it — Claude does
not write its own commentary into Notes. Every distinct section/appendix
referenced on a page is linked to its own eCFR page; there is no single
blanket "sources" blurb anywhere.

All quotes were transcribed by downloading the official govinfo.gov PDF of
31 CFR Part 356 (`CFR-2025-title31-vol2`) and reading the extracted text
directly (`pdftotext`, no `-layout` flag — that flag interleaves the
source's two-column layout and garbles reading order) — not paraphrased,
and not passed through any AI summarization step.

Page 0 covers Security, Marketable security, and CUSIP number (§356.2). Page
1 covers Par, Par amount, Principal (not independently defined in Part 356 —
see §356.30 and Appendix C §I.A, which does confirm the "whichever is
greater" par-amount floor at maturity for inflation-protected securities),
Face value (not a CFR term at all — a practical formula: par amount ×
quantity), and Price. Pages 2–4 cover Treasury bills/notes/bonds verbatim
from §356.5 ("What types of securities does the Treasury auction?"), split
one-per-page because the Notes/Bonds subsections are long; TIPS is the
inflation-protected variant of a Note (§356.5(b)(2)) or a Bond (§356.5(c)(2))
— the deck shows this via the CFR's own structure (separately numbered
sub-items under Notes and Bonds), not as added commentary. Page 5 covers the
three §356.2 date definitions. No diagram on any of these pages — text-only
pending direction on visual treatment. Discount/Discount amount and
Premium/Premium amount are not covered. "Bond" is avoided as informal
shorthand for "security" throughout, since the CFR uses "bond" for one
specific security type; FRNs are avoided as the subject of illustrative
examples.

"Live"/calculator pages are seeded from real, currently-outstanding
securities fetched from R2 at load time; they show a loading/error state
instead of rendering until that fetch resolves (see `index.html`'s
`renderCurrent()`).

## Content-driven architecture

`content/deck.md` is the single file that defines both the deck's structure
and its text — edit it directly to reorder pages, retitle a chapter, or
change any sentence; no JS edit is needed for content changes. `index.html`
has zero page-specific text or ordering in it; it fetches and parses this
file at load time and builds the stage/TOC/dots from the result.

**Page syntax:**
```
# page-id
ch: 4 · TIPS & the CPI Index
title: CPI & "The Index"

<blocks...>
```
`page-id` fixes both the page's identity (used to attach a calculator, see
below) and its position — file order is deck order. `ch`/`title` may be left
blank per the standing practice above.

**Block syntax**, inside a page's body:
- `## Term` starts a definition card. If the body underneath contains
  `### CFR`, `### Usage`, or `### Notes` sub-headers (each field's text runs
  until the next `### ` sub-header or the next block), it renders as a full
  CFR/Usage/Notes review card — Notes always renders even if left blank, so
  its slot is visible. With no sub-headers, the heading's body is treated as
  plain paragraph(s) — a simple content card, no Usage/Notes rows. Fields
  are `###` sub-headers rather than inline `Label:` prefixes specifically so
  they're visually distinct from the field text when hand-editing.
- `### CFR-list` (in place of `### CFR`) mirrors §356.5's own
  lettered/numbered outline: `(1) Section label` lines start a new labeled
  group, `- item` lines are bullets under the current group, and one
  trailing bare line is the section's citation. Used for Bills/Notes/Bonds.
- `:::lead`, `:::example`, `:::callout`, `:::aside` — fenced free-text
  blocks, each rendering as the matching styled element.
- `:::table` — a fenced pipe table (`| cell | cell |` per row, first row is
  the header row).
- `:::card-table Term Name` — a table embedded inside a titled card (used
  for the PRICE-frequency table).
- `:::grid2 ... :::` — a fence containing several `## ` mini-cards, laid out
  two columns wide (used for the P/C/i/n/vⁿ/aₙ symbol cards).
- Citations: `[[356.5:§356.5(b)(1)(iv)]]` — the part before `:` is the eCFR
  URL key (see `CFR_URL` in `deck-manager.js`), the part after is the
  display label; renders as a linked, parenthesized citation.
- Inline formatting: `__underline__`, `**bold**`, `*italic*`,
  `` `code` ``. Raw HTML (e.g. `<sup>n</sup>`) passes through untouched —
  this is trusted, hand-authored content, not user input.

Calculator pages (Index Ratio, Inflation-Adjusted Principal, Price vs.
Yield, PRICE, Bill Pricing) still have a `deck.md` section for their static
lead-in text — except where that text itself has to quote a live number
(e.g. "a real 4.125% note, CUSIP ...", which changes as securities roll off
and on), in which case the whole lead sentence stays code-generated in
`primer-calcs.js` since it cannot be static prose. Every calculator page's
*widget* (inputs, outputs, event wiring) is data-driven JS, keyed by page id
in `CALCS` (`primer-calcs.js`) and mounted after that page's static blocks
render — `deck.md` has no representation for the widget itself, only
whatever static text precedes it.

## Architecture

No build step; ES modules served statically.

| Module | Role |
|--------|------|
| `index.html` | Shell: CSS, topbar/TOC/pager chrome, navigation. Builds `PAGES` from `loadDeck()`; no page-specific business logic. |
| `content/deck.md` | Every page's structure and static content — see "Content-driven architecture" above |
| `src/deck-manager.js` | Parses `content/deck.md` (`loadDeck()`) and renders its blocks to HTML (`renderBlocks()`). The only module that understands the `.md` syntax; holds no page text itself |
| `src/primer-calcs.js` | The 5 calculator widgets' input/output wiring only (`CALCS` map, keyed by page id) — no static prose |
| `src/primer-data.js` | R2 fetch (`loadPrimerData()`), featured-security pickers (`pickFeaturedTips/Note/ShortBill/LongBill`), `baseCpiFor()`, re-exports `lookupRefCpi` |
| `src/primer-bills.js` | `discountRateToPrice`/`priceToDiscountRate` (Appendix B §VI.A/§VI.C) — genuinely new math, not duplicated elsewhere in this suite |

### The frequency rule (Ch. 7–8)

Spreadsheet `PRICE`/`YIELD` with `frequency = 2` reproduces Appendix B's
compounded formulas for notes, bonds, TIPS, and bills with more than 26 weeks
to maturity. For bills with 26 weeks or less to maturity, frequency 2 places
settlement inside a single semiannual period, which collapses `PRICE`'s
"one period or less" rule to a simple (non-compounded) day-count formula —
which is what `shared/src/bond-math.js`'s `yieldFromPrice()` already
special-cases below ~182.5 days. Verified numerically against both of
Appendix B §VI.D's own worked examples (52-week bill → 8.237%, 20-day bill →
8.076%) before writing the Ch. 7/8 content.

### Data source & fallback

Every "live" page needs the R2 fetch to succeed; there is no offline fallback
(a "data unavailable" message renders instead). Local dev servers hit CORS
when fetching R2 directly from `localhost` — this is expected (see
SeasonalAdjustments' spec for the same issue) and not a bug; verification
against real data used `page.route()` to serve curl-fetched CSV snapshots.
