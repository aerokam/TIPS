## Form Card Layout

Five stacked rows inside `.form-card`, grouped by how the user thinks about them — what to build,
how to build it, then act on it — rather than by control type, so the card reads as one coherent
form (3.0 §Per-Rung DARA Selection; the DARA Plan card and its split-year/segment tools were
removed in favor of selecting rungs directly on the ladder table).

### Row 1 — Ladder target (`.card-inputs`)
Flexbox, `gap: 8px 20px`, `align-items: flex-end`.  
Contains: Import (`#import-menu`, §Import/Export Menus below), DARA, First Year (mode-dep), Last Year
(mode-dep), Brackets (`#bracket-mode`, rebalance-only — 2-bracket/3-bracket, with its own "?" help
button), Pre-ladder int.

No yield-source control is exposed here — the card is already crowded, especially in Build mode. The market-data source is a single hardcoded constant (`YIELD_SOURCE` in `index.html`) rather than a user-facing choice; see 3.1 §4.0 Yield Sources.

### Row 2 — Construction policy + Export (`.card-inputs`, `margin-top: 8px`)
Contains: Maturity preference (`#build-maturity`, 2.0 §Maturity Selection Within a Funded Year —
"Select maturities…" opens the maturity-picker modal), Coupon pick (`#build-coupon`, hidden unless
Maturity preference is not "Last to mature"), Allocation policy (`#rebal-alloc-policy` + its "?"
help button, Rebalance-only, disabled and forced to "Maturity order" whenever Maturity preference is
"Last to mature"/"First to mature" — 2.0 §Within-Year Allocation Policy; "Set priority order…" opens
the priority-order modal, §Priority-Order Picker below), then **Export** (`#export-menu`, §Import/
Export Menus below). All four items are shared between both modes and live regardless of whether a
run has happened — grouped together as the row of things you set up *before* running, as opposed to
Row 3's run-gated actions. (Export itself is a partial exception: two of its three options need a
completed run — see §Import/Export Menus.)

### Row 3 — Run + Post-Run Actions (`.card-inputs`, `margin-top: 8px`)
Contains, in order: **Run button first** (`#run-btn`, "Rebalance Ladder"/"Build Ladder" depending on
mode — deliberately the first item of Row 3, not the last item of Row 1: it's always visible, just
disabled pre-load, unlike everything after it which stays `display:none` until a run happens), then
Trade Ticket (opens the cost-breakdown modal, see 5.0 §Trade Ticket), **Cash Flow** (`#cash-flow-btn`,
opens the payment calendar, see 5.0 §Cash Flow Calendar), and Duration links.

**Cash Flow is gated differently from the rest of Row 3.** It shows as soon as holdings are loaded
(`currentHoldingsArray && tipsMap && refCpiRows`) — it is a fact about the currently held TIPS, not a
ladder-construction result, so it does not wait for Run. Trade Ticket and Duration links stay
`display:none` until a run completes, since each depends on `buildDetails`/`rebalDetails`.
All items `align-self: flex-end`.

### Import/Export Menus (`#import-menu` in Row 1, `#export-menu` in Row 2)

Two `<select>` elements act as action menus rather than persisted-state fields: choosing an option
performs that action immediately (opening a file picker, or triggering a download), then the select
resets straight back to its placeholder (`Import…` / `Export…`) — there is no "currently selected"
value to leave showing, unlike `#build-maturity`/`#rebal-alloc-policy`'s "Select maturities…"/"Set
priority order…" options, which stay selected as an ongoing state and need the click/mousedown
disambiguation described in §Priority-Order Picker below. That disambiguation isn't needed here since
every choice always starts from the placeholder and a genuine `change` event fires every time.

**Import** (`#import-menu`, Row 1) replaces the old plain "Browse" button:
- **CUSIP/Qty** — Rebalance-only (hidden in Build, no holdings to browse for): opens the same
  `#holdings-file` picker the old Browse button opened, auto-detecting broker files or a previously
  exported CUSIP/Qty file (2.1 §Supported Formats). The loaded filename still displays next to the
  menu (`#holdings-file-name`), hidden in Build where there's no such file.
- **DARA Plan** — both modes: opens the `#dara-plan-import-file` picker (2.1 §Standalone DARA-plan
  file).

**Export** (`#export-menu`, Row 2):
- **Ladder CSV** — the full rendered table, disabled until a run completes for the current mode.
- **CUSIP/Qty** — Format 5 (2.1 §Format 5), disabled until a run completes for the current mode.
- **DARA Plan** — the standalone year→DARA file (2.1 §Standalone DARA-plan file), enabled any time
  there's per-year DARA to save (no run required).

The two run-gated Export options are re-synced (`_syncExportMenu()`) everywhere `rebalanceRendered`/
`buildRendered` changes — mode switch, both render functions, and every output-clearing reset — the
same set of call sites the old `#export-csv-btn`/`#export-cusip-qty-btn` buttons' `display` toggle
used to cover.

**Duration link button labels:** `Gap Dur` (gap/bracket duration calcs popup), `Future 30Y Dur`.

### Row 4 — Post-Run Stats (`#ladder-stats-display`, `margin-top: 4px`)
A row-flex container (`flex-direction:row; gap:16px; align-items:center`) holding four stats side by
side, shown after run (both modes). Hidden (`display:none`) until a result is available; shown as
`display:flex`.

- **`#avg-yld-display`**: `Avg Yld <value>%` — portfolio weighted average yield (%).
- **`#avg-sa-yld-display`**: `Avg SA Yld <value>%` — portfolio weighted average SA yield (%; 4.0
  §Weighted Modified Duration `weightedAvgSaYield`, same market-value weights as Avg Yld/Avg Mod
  Dur — 2.0 §Within-Year Allocation Policy Part A).
- **`#wad-display`**: `Avg Mod Dur <value>` — portfolio weighted modified duration (dimensionless;
  no unit suffix).
- **`#net-cash-inline`**: Net Cash (rebalance) / Total Cost (build) label + value.

All four use `.info-stat` / `.info-stat-val` styling (Net Cash/Total Cost additionally uses
`.nc-label`/`.nc-val`, §Row 5 typography table below).

### Row 5 — Info Strip (`.card-info`)
Single flex row, `gap: 12px`, `align-items: center`, `margin-top: 6px`, `padding-top: 6px`, `border-top: 1px solid rgba(255,255,255,0.12)`.

**Info strip typography:**

| Class / ID | Font size | Weight | Color |
|---|---|---|---|
| `.info-muted` (`#info-source`) | `13px` | normal | `var(--portal-card-text)` @85% opacity |
| `.info-sep` (` · ` separators) | `13px` | normal | `var(--portal-card-text)` @40% opacity |
| `.info-stat` (Term, Range labels) | `13px` | normal | `var(--portal-card-text)` |
| `.info-stat-val` (Term/Range values) | `15px` | `700` | `#fff` |
| `#info-tips-count` | `15px` | `700` | `#fff` |

**`#info-source`** (`_buildRows()`) is one `.info-muted` span holding "Trade: `<date>` · Settle:
`<date>` · Ref CPI: `<date>`" — the trailing Ref CPI date is itself the clickable RefCPI-override
link (3.0 §RefCPI Date Override), not a separate labeled stat.

**Info strip content order:** `#info-source` (Trade/Settle/Ref CPI) · Term · Range · `·` · TIPS
count. **Net Cash / Total Cost is not in this row** — it moved to Row 3 (`#net-cash-inline`,
`.nc-label`/`.nc-val`, `13px`/`700` and `16px`/`800` respectively) alongside the other post-run
stats, so it's visible the moment a run completes rather than tucked into the always-present info
strip below it.

## Selection Toolbar

`#selection-toolbar` (3.0 §Per-Rung DARA Selection) replaces the removed DARA Plan card. It is a
child of `#top-row`, placed right after `#table-controls`, so it sticks with the rest of the card
instead of scrolling in normal page flow — a plain sibling there could scroll up and land underneath
the sticky card as the ladder table below grew taller. Light-themed to match the table beneath it
rather than the dark form card above — `display:none` until at least one funded-year rung is
selected on the table, then `display:flex; align-items:center; gap:10px`.

Contents, left to right: a year-range label (`#selection-label`, e.g. "2028–2031 selected (4
rungs)"), a **Set DARA** number input (`#selection-dara-input`) + Apply button
(`#selection-set-btn`), an **Infer DARA** button (`#selection-infer-btn`, Rebalance only —
`display:none` in Build, no holdings to self-finance against), and a **Clear** button
(`#selection-clear-btn`).

Infer DARA solves one flat self-financing value across the selected rungs (3.0 §Per-Rung DARA
Selection), so after it runs, `#selection-dara-input` is set to that value — the field reflects
what was just solved rather than staying on whatever was last typed.

Selecting rungs (click / Shift-click / click-drag on a funded-year group-header row, 3.0 §Per-Rung
DARA Selection §Selecting rungs) also gets a highlight: `tr.fy-group-header.selected td { background:
#ffe9a8 !important }`. The drag-starting `mousedown` calls `preventDefault()` (plus `user-select:
none` on group-header cells as a backstop) so dragging across rows doesn't also paint the browser's
own native text-selection highlight underneath it. A separate `tr.fy-group-header.selected:hover td`
rule (same specificity as the plain `:hover` rules, placed after them so source order decides)
keeps the yellow highlight showing while the cursor still sits over a just-selected row mid-drag —
without it, the hover teal would win and the row under the cursor would look unselected until the
mouse moved off it.

There is no Undo or Revert-to-loaded control (3.0 §No edit history) — both were removed once
selection-based editing made walking back a mistake as easy as making the original edit again.

## Priority-Order Picker

`#rank-picker-overlay` / `#rank-picker-modal` — the per-year override modal for 2.0 §Within-Year
Allocation Policy's Part D, opened via Row 2's Allocation policy dropdown's "Set priority order…"
choice (same mousedown/change/click relabeling pattern as the Select-maturities picker, §Form Card
Layout Row 2 above, duplicated for `#rebal-alloc-policy`). Structurally parallel to the maturity
picker: same
draggable/resizable modal frame (`makeDraggableResizable`, `src/modal.js`), same close/cancel/apply
button row.

**One modal covers every year in range**, not a per-year launcher — an earlier revision added a
small icon next to each funded year's inline DARA input to open this modal pre-scrolled to that year;
it was removed once the Allocation policy dropdown became the single obvious entry point, since every
icon opened the identical whole-ladder modal (redundant once there's one clear home for "priority
order").

Each year renders as a row of **chips** — one per candidate/held CUSIP, current-priority order —
with **◀ / ▶** buttons on each chip to reorder (not ▲/▼: the chips lay out horizontally, so
left/right matches the actual direction a reorder click moves a chip; an earlier version used ▲/▼ and
was corrected). `#rank-picker-desc` states the convention: "Left = preferred to hold/buy first. Right
= sold first if this year needs to shrink." — plus a note that under Equal split a not-held maturity
can rank ahead of a held one (2.0 §Within-Year Allocation Policy), so that isn't a bug when seen in
the picker. A year left untouched follows whatever the global policy currently produces for it
(`rankForYear`, seeded via `_rankPickerYearOrder`) — opening and Applying with no edits is a no-op.
Apply writes to `_yearRankOverrides`; picking a different named global policy clears every override
(2.0 §Within-Year Allocation Policy).

## Modal Frame Standard

Every modal with substantial content (more than a couple of short lines) uses the shared
draggable/resizable frame (`makeDraggableResizable`, `src/modal.js`) — a fixed-position,
`display:flex; flex-direction:column` panel with a `cursor:move` title bar and 8 `.resize-handle`
divs (n/s/e/w/nw/ne/sw/se). Applies to: TipsRef, the maturity picker, the priority-order picker
(both above), Trade Ticket, and the Cash Flow Calendar (5.0 §Trade Ticket, §Cash Flow Calendar).
`makeDraggableResizable(modalEl, titleEl, { minWidth, minHeight })` is called once per modal at
startup, alongside the others.

Small, fixed-content modals (help, account selection) are exempt — nothing in them benefits from
resizing, and a plain centered overlay is simpler.

## Per-Year DARA (Table-Integrated)

### Removal of the standalone panel

The standalone Per-Year DARA panel (`#dara-by-year`) described in earlier revisions of this spec is
**removed as a separate UI element**, in both Rebalance and Build. Its input surface moves into the
ladder output table itself — a compact editable DARA element in each funded-year group header row,
next to the funded-year integer, occupying the Maturity column's cell position (5.0 §Funded Year
Group Header Row §DARA Input; the Maturity column header text also changes to "DARA / Maturity",
5.0 §Shared columns).

**What is unchanged.** The underlying store mechanics are untouched by this move — `_daraByYearStore`,
`getDaraByYear()`, the selection toolbar's Set DARA / Infer DARA (§Selection Toolbar above), and the
standalone DARA-plan file import/export all continue to exist exactly as specified
(3.0 §Per-Year DARA (`daraByYear`), §Per-Rung DARA Selection) — only the **input surface** moved out
of a dedicated panel.

### Persistence rule (unchanged)

**User-modified values are authoritative and must survive re-renders.** Specifically:
- Every year the user edits is stored in `_daraByYearStore` (a `Map<fundedYear, number>`).
- `_daraByYearStore` is the source of truth for modified years. The DOM input values are a view.
- `getDaraByYear()` must consult `_daraByYearStore` first for each year; only fall back to the DOM
  input value for years not yet in the store.

### DARA field display (unchanged)

- When any stored year value differs from `_daraByYearPanelDefault`, the main `#dara` field shows
  **by year** (purple weight) instead of a numeric value.
- The underlying default (`_daraByYearPanelDefault`) is preserved in memory so `_getDefaultDara()`
  can return it while the field shows **by year**.
- Clicking ▲/▼ step buttons updates `_daraByYearPanelDefault` and overwrites **all** store entries
  to the new step value — the intent is to set all years uniformly.
- **`updateDaraInput(force)` overwrites a non-empty field too when `force` is true**, not just when
  it's empty. The un-forced path only fills a blank field (so it never clobbers a number the user is
  actively typing) and otherwise leaves whatever text is already there alone — correct while the user
  types, but wrong for a programmatic restore (Apply/Import): the field could be showing
  stale pre-restore text while the store has already moved on to a *different* flat value, and the
  un-forced rule would leave that stale text on screen even though `force=true` was passed (bypassing
  only the active-element guard, not this check) — e.g. Apply in Build mode restoring a flat plan
  before any ladder had been built left the top field on its old number even though every per-year
  row (once built) correctly showed the restored one. `force=true` now means the field is
  unconditionally resynced to `_daraByYearPanelDefault` whenever the store isn't by-year.

### Year list (unchanged)

**Build mode:** every year in `[firstYear, lastYear]` gets a group header row and DARA input:
- Funded years (actual TIPS) — no label suffix
- Gap years (2037–2039, TIPS not yet issued) — labelled `(gap)`; a custom DARA increases synthetic gap quantities and therefore bracket excess
- Future 30Y years (beyond last issued TIPS, currently 2056) — labelled `(30Y)`, shown only when `lastYear > maxTipsYear`; a custom DARA increases hypothetical future 30Y quantities and therefore future 30Y cover excess

**Rebalance mode:** every year in `[firstYear, lastYear]` gets a group header row and DARA input. Gap years within that range are labelled `(gap)`.

Years absent from the map fall back to the scalar DARA.

*Open question (flagged, not resolved here): whether the `(gap)`/`(30Y)` label suffixes remain
literal text next to the inline DARA element, or are dropped as redundant now that the row itself
already signals gap/Future-30Y years via the Gap/Future 30Y sub-row structure (5.0 §Sub-Row Logic).
Left to the code pass.*

### Why the maturing-proceeds/LMI breakdown stays in the popup

The old standalone panel surfaced (or was seen by some users as conflating) the maturing-proceeds-
vs-LMI breakdown for a year. That breakdown is **not** promoted into new inline columns on the table
row — it stays exactly where it already lives, the existing Amount Before / Amount After drill-down
popup (5.0 §Popup Routing, `amtBefore` / `amtAfter` / `amount`). This was a deliberate choice,
considered and rejected in favor of inline columns, so a future reader should not "fix" this by
re-adding columns for it.

## Before-State on Load (Rebalance)

The ladder output table renders **before Run is clicked**: as soon as holdings are loaded /
account(s) selected in Rebalance mode, Qty Before / Cost Before / Amount Before render for every
ordinary funded year (3.0 §Before-State Preview and Bracket-Year Excess Detection).

**`#table-controls` (Expand All / Collapse All, §Collapsible Groups below) is available as soon as
this before-state table renders** — the ladder table with its collapsible funded-year groups is
already fully visible pre-Run, so those two buttons are usable immediately too, not gated behind
Run. Only the genuinely **After**-dependent controls stay hidden or disabled until the user clicks
Run Rebalance and the After-side columns fill in: the Export menu's Ladder CSV / CUSIP-Qty options,
Trade Ticket, Duration links, and `#ladder-stats-display` (Avg Yld / Avg SA Yld / Avg Mod Dur / Net
Cash, §Row 3 above).
Build mode has no "Before" state and continues to render only after Run.

## Collapsible Groups

### Expand / Collapse All Buttons

Two secondary buttons — **Expand All** and **Collapse All** — are placed in `#table-controls`, a flex strip (`display:flex; gap:6px; padding:6px 16px 2px`) positioned directly above the output table divs (`#output`, `#build-output`). It's a child of `#top-row` (outside `.form-card` itself, but inside the sticky wrapper — §Selection Toolbar above explains why), so it stays pinned with the rest of the card rather than scrolling in normal page flow. `#table-controls` is hidden (`display:none`) until a result is available, then shown as `display:flex`.

Styling: same secondary-button class the Row 3 action buttons use (`outline` variant or equivalent). Labels: `Expand All` / `Collapse All`.

### Group Header Row Visual Style

| Property | Value |
|---|---|
| Background | `rgba(255,255,255,0.06)` — slightly lighter than data rows |
| Font weight | `700` |
| Color | `#fff` |
| Cursor | `pointer` |
| Toggle glyph | `▼` (expanded) or `▶` (collapsed); positioned before the funded year integer with `margin-right: 6px` |
| Bracket year | Append `*` to the funded year integer; header row also gets `background: rgba(173,216,230,0.15)` (matches light-blue bracket theme, but muted for the header) |

### Child Row Visibility

When a group is collapsed (`data-expanded="false"`):
- All `.fy-child` rows with matching `[data-fy]` receive the `hidden` attribute.
- All `.acct-subrow` rows with matching `[data-fy]` receive the `hidden` attribute.
- The group header row itself remains visible at all times.

When expanded:
- `hidden` is removed from all matching `.fy-child` and `.acct-subrow` rows.
- Excess sub-rows (`.excess-subrow.fy-child`) are revealed along with the main TIPS rows — they are inseparable children of their group.
- Individual per-TIPS account expansion state (set via `style.display`) is preserved: rows that were individually collapsed before the group was collapsed remain individually hidden after expansion.

### Default State

**Bracket/cover-year groups render expanded; ordinary funded-year groups render collapsed**
(`_setDefaultGroupsExpanded`: `data-expanded = hdr.classList.contains('bracket')` for every
`fy-group-header` row) — the excess holdings that make a bracket/cover row worth a second look are
visible at a glance without an extra click, while the common case (an ordinary single-TIPS year) stays
compact. "Expand All"/"Collapse All" (above) still act on every group regardless of this default.

### Expand/Collapse State Survives a Rebalance Ladder Re-run

Re-running Rebalance Ladder rebuilds `#simple-table`'s `innerHTML` from scratch, which would
otherwise reset every group back to the default above and discard whatever the user had opened.
Before the rebuild, `_captureExpandedState(simpleEl)` snapshots each funded year's current
`data-expanded`; after, `_restoreOrDefaultGroupsExpanded(simpleEl, snapshot)` re-applies it,
falling back to the normal bracket/cover-year default only for a funded year absent from the
snapshot (e.g. the year range grew). This makes it possible to expand the one or two years of
interest, change Maturity preference or Allocation policy, re-run, and see the effect immediately
without re-expanding anything (2.0 §Within-Year Allocation Policy). Scoped to Rebalance's own
re-run (`renderOutput`) — Build's table and the pre-first-run Before-state preview
(3.0 §Before-State Preview and Bracket-Year Excess Detection) are unaffected.

### Totals Row

The tfoot totals row is always visible regardless of group expand/collapse state. Its values are unchanged — they reflect the full ladder totals including excess (as before).
