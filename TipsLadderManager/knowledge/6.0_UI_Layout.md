## Form Card Layout

Three stacked rows inside `.form-card`:

### Row 1 — Inputs (`.card-inputs`)
Flexbox, `gap: 8px 20px`, `align-items: flex-end`.  
Contains: Holdings CSV, DARA, First Year (mode-dep), Last Year (mode-dep), Method, Retain lower bracket excess (rebalance-only checkbox, on by default, with its own "?" help button), Maturity preference (build-only), Coupon pick (build-only; conditional — only shown when Maturity preference is not "Last to mature", since that policy can never hit a same-month two-issue collision; has its own "?" help button next to the label), Pre-ladder int.

**Maturity preference's fifth choice, "Select maturities"** (2.0 §Picking Maturities for a Funded
Year), is mutually exclusive with the other four and opens a picker modal rather than sizing
directly. The choice relabels itself in place — "Select maturities" the first time it's chosen
(genuine value change → modal opens immediately), or after a Build has run and it's already the
active choice ("Edit maturities", shown only once the dropdown is reopened; a further reselect
opens the modal). No separate button exists anywhere in the card for this. First Year and Last Year
both hide entirely while Select maturities is active, since neither drives the build in that mode
(the pick set's latest year becomes the effective last year).

No yield-source control is exposed here — the card is already crowded, especially in Build mode. The market-data source is a single hardcoded constant (`YIELD_SOURCE` in `index.html`) rather than a user-facing choice; see 3.1 §4.0 Yield Sources.

### Row 2 — Actions (`.card-inputs`, `margin-top: 8px`)
Contains: Run button (`padding: 5px 18px`), Export CSV (post-run), Export CUSIP/Qty (post-run), Trade Ticket (post-run — opens the cost-breakdown modal, see 5.0 §Trade Ticket), Duration links, `#wad-display` (post-run).  
All items `align-self: flex-end`.

**Duration link button labels:** `Gap Dur` (gap/bracket duration calcs popup), `Future 30Y Dur`.

**`#ladder-stats-display`** — shown after run (both modes). A column-flex container (`flex-direction:column; gap:2px; align-items:flex-end`) holding two stacked stats, positioned immediately to the right of `#duration-links`. Hidden (`display:none`) until a result is available; shown as `display:flex`.

- **Row 1 — `#avg-yld-display`**: `Avg Yld <value>%` — portfolio weighted average yield (%).
- **Row 2 — `#wad-display`**: `Avg Mod Dur <value>` — portfolio weighted modified duration (dimensionless; no unit suffix).

Both use `.info-stat` / `.info-stat-val` styling.

### Row 3 — Info Strip (`.card-info`)
Single flex row, `gap: 12px`, `align-items: center`, `margin-top: 6px`, `padding-top: 6px`, `border-top: 1px solid rgba(255,255,255,0.12)`.

## DARA Plan Card

### Purpose

The DARA Plan card (`#dara-plan-card`) holds the plan-level controls that act on the whole per-year DARA shape rather than a single year: split-year chips + add-select, each segment's row (label, **Infer DARA** button in rebalance, the **$ each** constant-stamp input), Undo/Revert, and the Save DARA Plan / Export / Import controls (3.0 §Segmented DARA, §Persisting a DARA plan across sessions). These outgrew being a minor sub-panel — they're integral ladder-management controls, not an appendix to the raw per-year table — so the card gets the **same visual weight as the main form card** (`.dara-plan-card`: same background/border/shadow as `.form-card`, but a normal `border-radius: 8px` on all corners since it isn't flush against the tab bar).

`#dara-plan-body`'s children are ordered by how often each one needs to be seen and acted on, most-urgent first: the saved-plan-found Apply/Dismiss banner (`#dara-plan-banner`) leads, since an unactioned saved plan is the thing most likely to need a decision the moment the card opens; then Undo/Revert (`#dara-history-tools`); then the Save row (`#dara-remember-row`: the Save DARA Plan button, the "✓ Saved" flash, and the "⋮" menu holding Export/Import — 3.0 §Standalone DARA-plan file); then the split-year/segment tools (`#dara-seg-tools`). Export/Import are tucked behind the "⋮" menu rather than shown as their own buttons — Save (localStorage, same device) covers the common case, and the two-click file-based path is for the less-frequent cross-device/cross-browser case.

### Placement and visibility

A dropdown, not a static block: `#dara-plan-card` is a normal-flow DOM child of `#top-row` (the
sticky main-card container). It pushes the ladder output table (`#output` / `#build-output`) below
it down when open — same push-layout behavior described below — rather than overlaying it; an
earlier `position: absolute` overlay version blocked clicks on the table underneath, which broke the
normal workflow of editing per-year rungs while the plan tools are open. Being a child of `#top-row`
(`position: sticky`) is what keeps it from scrolling away independently: the sticky row just
grows/shrinks in place as the dropdown opens/closes.

**Note (table-integrated DARA):** this section predates the removal of the standalone Per-Year DARA
panel (§Per-Year DARA (Table-Integrated) below) — per-year DARA is now entered inline in the ladder
output table's group header rows, not in a separate panel below this card. The card now sits
directly above that output table rather than above a dedicated DARA panel. Its *availability*
(whether it's relevant at all — valid DARA + range, holdings loaded in rebalance) still tracks the
same condition that used to gate the standalone panel; the exact call site this is wired from
(previously three sites inside `renderDaraByYearPanel()`) is a code-pass detail, not resolved here —
when unavailable, the whole card (header sliver included) is hidden, same as before.

When available, the card always shows its header sliver (`#dara-plan-hdr`: a glyph, "Show DARA
Plan" / "Hide DARA Plan" label, and the badge dot below) — this is the click target. There is no
separate toggle button elsewhere in the main card; the sliver *is* the control, so it's never more
than one click away regardless of scroll position (it's inside `#top-row`, `position: sticky`) or
whether a saved plan was ever found. Clicking it expands/collapses `#dara-plan-body` (the actual
split-year/segment/Save/history controls), tracked by `_daraPlanOpen` and set via
`_setDaraPlanOpen()` — closed by default, so a plain flat-DARA ladder that never touches
segments/Save/history never shows more than the one-line sliver. `_updateDaraRememberUI` also
calls `_setDaraPlanOpen(true)` when a saved plan is found for the current cache key — since a
passive dismissible banner alone was easy to scroll past. A badge dot (`.needs-attention` on
`#dara-plan-hdr`, driven by `_daraPlanNeedsAttention`) persists even if the user collapses the body
again without clicking Apply/Dismiss, so the found-a-saved-plan state can't be silently lost;
cleared by the Apply and Dismiss handlers.

A second, separate signal covers the opposite direction — an unsaved edit rather than an unactioned
saved plan. Any per-year value change (per-rung edit, segment Infer/`$ each`, the flat `#dara`
field, Undo, Revert) calls `_setDaraPlanDirty(true)` (3.0 §Persisting a DARA plan across sessions),
which also auto-opens the card via `_setDaraPlanOpen(true)` if collapsed, and rings
`#dara-remember-btn` (`.needs-save`, see Styling) rather than the header badge dot — the two states
are deliberately distinct (a header-level "something needs a decision" vs. a button-level "click
this one control"), so they never overwrite each other's indicator. Cleared by Save or Apply.

### Styling

Buttons, chips, inputs, and selects inside `.dara-plan-card` use the same teal-card token set as the main card's own controls (`.plan-btn` ≈ secondary button on `--portal-header-bg`, including the Save DARA Plan button itself and the "⋮" more-menu toggle (`#dara-plan-more-btn`); `.plan-chip` for split-year chips; `.plan-banner` for the saved-plan-found Apply/Dismiss banner) rather than the light-background styling still used by the plain Per-Year DARA table box below it. `.plan-btn.needs-save` (a red outline ring, same accent as the header badge dot) highlights `#dara-remember-btn` while `_daraPlanDirty` is true. The "⋮" menu (`#dara-plan-more-menu`) is a small absolutely-positioned dropdown anchored under the toggle, holding the Export/Import buttons; it opens on click and closes on an outside click or on either button firing its action.

## Per-Year DARA (Table-Integrated)

### Removal of the standalone panel

The standalone Per-Year DARA panel (`#dara-by-year`) described in earlier revisions of this spec is
**removed as a separate UI element**, in both Rebalance and Build. Its input surface moves into the
ladder output table itself — a compact editable DARA element in each funded-year group header row,
next to the funded-year integer, occupying the Maturity column's cell position (5.0 §Funded Year
Group Header Row §DARA Input; the Maturity column header text also changes to "DARA / Maturity",
5.0 §Shared columns).

**What is unchanged.** The underlying store/persistence mechanics are untouched by this move —
`_daraByYearStore`, `getDaraByYear()`, the DARA Plan card's split-year/segment/Infer/Undo/Revert
controls, the localStorage cache ("Save DARA Plan" button), and the standalone DARA-plan file
import/export (now reached via the "⋮" menu, see Styling above) all continue to exist exactly as
specified (3.0 §Per-Year DARA (`daraByYear`), §Segmented DARA, §Persisting a DARA plan across
sessions) — only the **input surface** moved out of a dedicated panel.

### Persistence rule (unchanged)

**User-modified values are authoritative and must survive re-renders.** Specifically:
- Every year the user edits is stored in `_daraByYearStore` (a `Map<fundedYear, number>`).
- `_daraByYearStore` is the source of truth for modified years. The DOM input values are a view.
- `getDaraByYear()` must consult `_daraByYearStore` first for each year; only fall back to the DOM
  input value for years not yet in the store.

### DARA field display (unchanged)

- When any stored year value differs from `_daraByYearPanelDefault`, the main `#dara` field shows
  **by year** (purple weight) instead of a numeric value.
- The underlying default (`_daraByYearPanelDefault`) is preserved in memory so `_getDefaultDara()`
  can return it while the field shows **by year**.
- Clicking ▲/▼ step buttons updates `_daraByYearPanelDefault` and overwrites **all** store entries
  to the new step value — the intent is to set all years uniformly.

### Year list (unchanged)

**Build mode:** every year in `[firstYear, lastYear]` gets a group header row and DARA input:
- Funded years (actual TIPS) — no label suffix
- Gap years (2037–2039, TIPS not yet issued) — labelled `(gap)`; a custom DARA increases synthetic gap quantities and therefore bracket excess
- Future 30Y years (beyond last issued TIPS, currently 2056) — labelled `(30Y)`, shown only when `lastYear > maxTipsYear`; a custom DARA increases hypothetical future 30Y quantities and therefore future 30Y cover excess

**Rebalance mode:** every year in `[firstYear, lastYear]` gets a group header row and DARA input. Gap years within that range are labelled `(gap)`.

Years absent from the map fall back to the scalar DARA.

*Open question (flagged, not resolved here): whether the `(gap)`/`(30Y)` label suffixes remain
literal text next to the inline DARA element, or are dropped as redundant now that the row itself
already signals gap/Future-30Y years via the Gap/Future 30Y sub-row structure (5.0 §Sub-Row Logic).
Left to the code pass.*

### Why the maturing-proceeds/LMI breakdown stays in the popup

The old standalone panel surfaced (or was seen by some users as conflating) the maturing-proceeds-
vs-LMI breakdown for a year. That breakdown is **not** promoted into new inline columns on the table
row — it stays exactly where it already lives, the existing Amount Before / Amount After drill-down
popup (5.0 §Popup Routing, `amtBefore` / `amtAfter` / `amount`). This was a deliberate choice,
considered and rejected in favor of inline columns, so a future reader should not "fix" this by
re-adding columns for it.

## Before-State on Load (Rebalance)

The ladder output table renders **before Run is clicked**: as soon as holdings are loaded /
account(s) selected in Rebalance mode, Qty Before / Cost Before / Amount Before render for every
ordinary funded year (3.0 §Before-State Preview and Bracket-Year Excess Detection).

**`#table-controls` (Expand All / Collapse All, §Collapsible Groups below) is available as soon as
this before-state table renders** — the ladder table with its collapsible funded-year groups is
already fully visible pre-Run, so those two buttons are usable immediately too, not gated behind
Run. Only the genuinely **After**-dependent controls stay hidden until the user clicks Run
Rebalance and the After-side columns fill in: Export CSV, Export CUSIP/Qty, Trade Ticket, Duration
links, and `#ladder-stats-display` (Avg Yld / Avg Mod Dur, §Row 2 above). Build mode has no
"Before" state and continues to render only after Run.

## Collapsible Groups

### Expand / Collapse All Buttons

Two secondary buttons — **Expand All** and **Collapse All** — are placed in `#table-controls`, a flex strip (`display:flex; gap:6px; padding:6px 16px 2px`) positioned directly above the output table divs (`#output`, `#build-output`), outside the form card. `#table-controls` is hidden (`display:none`) until a result is available, then shown as `display:flex`.

Styling: same secondary-button class as Export CSV buttons (`outline` variant or equivalent). Labels: `Expand All` / `Collapse All`.

### Group Header Row Visual Style

| Property | Value |
|---|---|
| Background | `rgba(255,255,255,0.06)` — slightly lighter than data rows |
| Font weight | `700` |
| Color | `#fff` |
| Cursor | `pointer` |
| Toggle glyph | `▼` (expanded) or `▶` (collapsed); positioned before the funded year integer with `margin-right: 6px` |
| Bracket year | Append `*` to the funded year integer; header row also gets `background: rgba(173,216,230,0.15)` (matches light-blue bracket theme, but muted for the header) |

### Child Row Visibility

When a group is collapsed (`data-expanded="false"`):
- All `.fy-child` rows with matching `[data-fy]` receive the `hidden` attribute.
- All `.acct-subrow` rows with matching `[data-fy]` receive the `hidden` attribute.
- The group header row itself remains visible at all times.

When expanded:
- `hidden` is removed from all matching `.fy-child` and `.acct-subrow` rows.
- Excess sub-rows (`.excess-subrow.fy-child`) are revealed along with the main TIPS rows — they are inseparable children of their group.
- Individual per-TIPS account expansion state (set via `style.display`) is preserved: rows that were individually collapsed before the group was collapsed remain individually hidden after expansion.

### Default State

All groups render expanded on initial table output. `data-expanded="true"` is set on every `fy-group-header` row; no `hidden` attributes are added to child rows.

### Totals Row

The tfoot totals row is always visible regardless of group expand/collapse state. Its values are unchanged — they reflect the full ladder totals including excess (as before).
