# 1.0 TIPS Reference — App Specification

## Dependencies

**Requires (read before modifying this spec):**
- `2.1 TIPS Basics` (`knowledge/TIPS_Basics.md`) — Ref CPI daily interpolation, Index Ratio, Par Value, inflation-adjusted coupon formula
- `DATA_DICTIONARY.md` — `RefCPI.csv` (S3) is a **daily** series; `Ref_CPI`, `Index Ratio`, `Par Value (Adjusted)` definitions
- `shared/src/ref-cpi.js` — canonical Ref CPI logic (retrieve-lookup, calc fallback, index ratio); imported, never copied
- `4.0 Computation Modules` §calculateDuration — canonical Macaulay/Modified duration algorithm (imported from `shared/src/bond-math.js`)
- `shared/src/market-data.js` (`loadMarketData()`) — canonical market-data fetch/parse and the single `YIELD_SOURCE` decision point, shared with TipsLadderManager
- `TipsLadderManager/knowledge/3.1_Data_Pipeline.md` §4.0 Yield Sources — the default (Fidelity market prices) vs. dormant (FedInvest cross-check) source, and their differing settlement-date conventions; TipsReference follows these identically, having previously priced off FedInvest directly with a uniform T+1 settlement that desynced from FedInvest's own T-settlement price/yield pairing
- `shared/src/settlement.js` — canonical bond-calendar primitives (`nextBusinessDay`, `parseHolidaySet`, `actualPaymentDate`)

Any change here that touches Ref CPI lookup, index ratio, coupon math, or the market-data source must remain consistent with these.

---

## Purpose

A standalone read-only reference table for all live TIPS issues. Combines the data from the **Ref** and **Mkt** popups in TIPS Ladder Manager into a single unified view, adding computed index ratio and adjusted price columns.

---

## Data Sources

TipsReference loads market data through `loadMarketData()` (`shared/src/market-data.js`) — the
same single entry point TipsLadderManager uses, so a `YIELD_SOURCE` flip applies to both apps at
once and TipsReference can never price off a different source than TipsLadderManager. See
`TipsLadderManager/knowledge/3.1_Data_Pipeline.md` §4.0 for the default (Fidelity market quotes)
vs. dormant (FedInvest cross-check) source and their settlement-date conventions — TipsReference
does not restate that machinery.

What TipsReference consumes from the returned shape:

| Field | Role |
|-------|------|
| `tipsRefRows` | **Primary source** — every TIPS ever issued (CUSIP, maturity, coupon, datedDate, baseCpi). Drives the row set; a CUSIP with no current market quote still appears, with Price/Yield/Term/Duration columns blank. |
| `yieldsRows` | **Enrichment** — price and yield for CUSIPs the active source currently quotes, joined onto `tipsRefRows` by CUSIP. |
| `refCpiRows` | date → refCpi lookup series (`RefCPI.csv`), used for Index Ratio / Adj Price / Cpn Date IR. |
| `bondHolidays` | SIFMA bond-market holiday set (`BondHolidaysSifma.csv`), used for coupon/maturity payment-date rolling (see Coupon roll-forward, below) — previously a hardcoded local `Set` covering only 2025–2027; now the same live-fetched set every other app uses. |
| `tradeDateStr`, `settleDateStr` | The as-of/"today" date and its T+1 settlement, source-dependent — drive the Price Date / Settlement header meta items and default Ref CPI date. |

## Columns (display order, left → right)

| # | Column | Source | Alignment | Format |
|---|--------|---------|-----------|--------|
| 1 | CUSIP | yields CSV | left | string |
| 2 | Maturity | yields CSV | left | MM/DD/YYYY |
| 3 | Coupon | yields CSV | right | 3 decimal places, % (e.g., 0.125%) |
| 4 | Dated Date | TipsRef.csv | left | string (YYYY-MM-DD) |
| 5 | Dated Date Ref CPI | TipsRef.baseCpi | right | 5 decimal places |
| 6 | Price | yields CSV | right | 3 decimal places |
| 7 | Index Ratio | computed | right | 5 decimal places |
| 8 | Adj Price | computed | right | 3 decimal places |
| 9 | Yield | yields CSV | right | 3 decimal places, % |
| 10 | Term | computed | right | 2 decimal places, y (e.g., 8.23y) |
| 11 | Mac Duration | computed | right | 2 decimal places |
| 12 | Mod Duration | computed | right | 2 decimal places |
| 13 | Cpn Date | computed | left | MM/DD/YYYY — tooltip: "Coupon payment date on or after the selected Ref CPI Date" |
| 14 | Cpn Date IR | computed | right | 5 decimal places — Index Ratio on the coupon date |
| 15 | Cpn $ / TIPS | computed | right | 4 decimal places (per $1,000 face value) |

### Computed Fields

```
settlementDate = loadMarketData()'s settleDateStr — source-dependent (3.1_Data_Pipeline.md §4.0)
refCpiDate     = user-selected date (default = settlementDate)
indexRatio     = refCPI / baseCpi                     // refCPI = lookupRefCpi(refCpiRows, refCpiDate)
adjPrice       = price × indexRatio
term           = (maturityDate − settlementDate) / (365.25 × 86400000)  // years, decimal — always T+1
macDuration    = calculateDuration(settlementDate, maturityDate, coupon, yield)  // always T+1
modDuration    = macDuration / (1 + yield/2)          // null if macDuration is null
nextCoupon     = _nextCouponOnOrAfter(refCpiDate, maturityDate)  // first coupon ≥ refCpiDate (inclusive)
cpnDateIR      = indexRatio(lookupRefCpi(refCpiRows, nextCoupon), baseCpi)   // shared/src/ref-cpi.js — truncate-6/round-5, same as the Index Ratio column
               // Index Ratio on the coupon date; null if nextCoupon date is beyond available RefCPI data
cpnPayment     = (coupon/2) × cpnDateIR × 1000
               // per $1,000 face; null if nextCoupon date is beyond the available daily RefCPI data
```

Where `maturityDate` is parsed from `tipsRefRows`' maturity string (TipsRef.csv — the primary source; see Data Sources above).

**Shared-module note:** TipsReference imports shared logic rather than copying it — Ref CPI logic from `shared/src/ref-cpi.js` (retrieve-lookup, calc fallback, index ratio) and duration from `shared/src/bond-math.js::calculateDuration`. Per the project-wide no-redundancy directive, these are defined once and never duplicated inline. See `4.0 §calculateDuration` for the canonical duration algorithm and [DATA_DICTIONARY.md#ref-cpi](../../knowledge/DATA_DICTIONARY.md#ref-cpi) for Ref CPI.

`indexRatio`, `adjPrice`, and `cpnPayment` use `lookupRefCpi(refCpiRows, date)`.

`RefCPI.csv` is the **authoritative** retrieved series (one row per calendar day, Treasury-interpolated value already applied; published forward several weeks past the current date). `lookupRefCpi` returns the **exact entry for the requested date** and `null` if the date is **outside the published range** — before the series starts, or past the last published day. The latter is why a future coupon date with no published Ref CPI yet (e.g. an October coupon when data runs only through July) shows `—` rather than a value. (Ref CPI is defined per specific calendar day; there is no fallback to an earlier date.) See [DATA_DICTIONARY.md#ref-cpi](../../knowledge/DATA_DICTIONARY.md#ref-cpi).

Term and duration are always anchored to T+1 settlement and do not change when the Ref CPI date is adjusted.

**Date distinction**: The **Price Date** header item is `loadMarketData()`'s `tradeDateStr` — the data's as-of/"today" date (Fidelity's download date by default; see 3.1_Data_Pipeline.md §4.0). Settlement is that source's T+1 (already computed by `loadMarketData()` as `settleDateStr`). Prices and yields come from the price date. Index ratio, adj price, and coupon use the **Ref CPI Date** (a user-selected picker defaulting to settlement); term and duration stay pinned to T+1 settlement regardless of the picker.

**Bond holidays**: `bondHolidays` comes from `loadMarketData()` (`BondHolidaysSifma.csv`, parsed via `shared/src/settlement.js` `parseHolidaySet`) — the live, maintained series every other app uses, not a hardcoded local list. Includes Good Friday, which bond markets close for (unlike equity markets).

**Matured TIPS**: once the maturity date of a TIPS is on or before today, Index Ratio and Adj Price are pinned to its own maturity date's Ref CPI rather than the globally selected Ref CPI Date — that is the realized principal redemption, not a function of a date the user can still move.

**Coupon roll-forward**: a coupon dated on a weekend or bond holiday is actually paid on the next Treasury business day, and Cpn Date / Cpn Date IR / Cpn $ track that effective payment date rather than the nominal semiannual date. This applies to every coupon a TIPS pays, outstanding or matured (a matured bond's final coupon coincides with its maturity date, so a maturity landing on a weekend/holiday keeps showing that final coupon through the day it actually pays). Because a coupon's calendar date can fall a few days before its effective payment date, the coupon search looks back up to 7 days from today, not just forward, so an already-past coupon that is only now being paid still shows as today's realized payment. Once that effective payment date has passed, the coupon columns clear (no projected coupon remains until the bond's next one) and, for a matured bond, the row drops out of the outstanding view (see Row Count above).

## Header

Fixed header bar contains (left → right):
- **← Portal** link (standard portal-link class)
- **Title**: "TIPS Reference"
- **Price Date** meta item (`loadMarketData()`'s `tradeDateStr`, formatted MM/DD/YYYY) — the data's as-of/"today" date, when prices were observed
- **Settlement** meta item (`loadMarketData()`'s `settleDateStr`, formatted MM/DD/YYYY) — date used for term/duration
- **Ref CPI Date** — the shared native date picker (`shared/src/date-picker.js`, classes `date-picker flush`; this app is the canonical look). Defaults to settlement date; user can select any date within the refCpiRows range (`min`/`max` bound to it); drives index ratio, adj price, and next coupon
- **Ref CPI** meta item (5 decimal places) — `lookupRefCpi` result for the selected Ref CPI Date
- **Status** message (loading / error, pushed to right via margin-left: auto)
- **Export CSV** button (disabled until data loads)

## Table Behavior

### Sorting
- Click a column header to sort ascending; click again to toggle descending.
- Active sort column shows ↑ or ↓ indicator.
- Default sort: Maturity ascending.
- Sort types: text columns (CUSIP, Maturity, Dated Date) use locale string compare; numeric columns use numeric compare (null treated as −∞).

### Filtering
- A filter input row sits below the header row (sticky).
- Each column has a text input; filtering is case-insensitive substring match on the **displayed** cell value.
- Active filters highlight in amber.
- Filtering and sorting are applied together on every input change.

### Row Count
- A row count bar below the header shows `N of M TIPS` (filtered vs. total).
- Next to the count, an **outstanding/all toggle button** controls whether matured TIPS are included. Default: outstanding-only (button reads "Show all"), equivalent to a maturity filter with today (`todayET()`) as the lower bound — the **effective payment date** (maturity, rolled forward to the next Treasury business day when maturity itself falls on a weekend or bond holiday) `>= today`. This keeps a TIPS visible through the day its final payment is actually made: a TIPS maturing on a weekend or holiday still shows on the following business day, when the payment posts. Clicking switches to showing all TIPS regardless of maturity (button reads "Show outstanding"). The toggle is applied before other column filters/date-range filters; `M` (the total) always reflects the full unfiltered universe, `N` reflects all active filters including the toggle.

## Export

Button label: **Export CSV**

- Exports the currently **filtered** rows in the current sort order.
- Columns match the display columns exactly (same labels, same formatted values) — **except Cpn $ / TIPS**, which exports at 6 decimal places instead of the on-screen 4. Coupon Rate and Index Ratio are both exact at their displayed precision (Index Ratio is already truncated/rounded to Treasury's own max precision, 5dp — see `indexRatio()` in `shared/src/ref-cpi.js`), so `cpnPayment` is an exact decimal; a consumer multiplying this per-$1,000 rate by a holding's Quantity to get actual coupon interest should round to cents once, on that final total, not on this rate first. Rounding the exported rate to only 4dp before that multiplication can shift the last cent at large quantities (worst case ~$0.05 at Quantity=1000); 6dp keeps that error undetectable at any realistic holding size.
- Filename: `tips-reference-<YYYY-MM-DD>.csv` where the date is the settlement date (T+1).
- Values containing commas are quoted.

## Design

- Stylesheet: `../shared/src/portal-theme.css`
- Full-viewport layout: header (fixed height) + row-count bar + scrollable table fills remaining height.
- No sidebar — all 15 columns are always visible.
- Table uses `border-collapse: separate` with sticky dual-row thead (header + filter).
- Hover row highlight: `#fffde7`.
- No sub-rows, no drilldowns.
- **Coupon calc modal**: clicking a non-null "Cpn $ / Bond" cell opens a help modal showing the calculation: CUSIP, coupon date, coupon rate, semi-annual rate, index ratio, then the formula in both symbolic and numeric form — `Index Ratio × (Coupon Rate / 2) × $1,000` followed by the same line with actual numbers — and the resulting payment (4 dp) per bond. Closes on ✕, overlay click, or Escape.

## Architecture

Single `index.html` with a `<script type="module">` that imports shared logic (`shared/src/ref-cpi.js`, `shared/src/bond-math.js`, `shared/src/market-data.js`, `shared/src/settlement.js`) — no build step, served directly from GitHub Pages. Per the project-wide no-redundancy directive, shared math is imported, never copied inline. (Earlier revisions of this spec mandated "no module imports / inline copies"; that was spec creep and is rescinded — TipsLadderManager already imports from `shared/src/market-data.js`, and duplication caused real Ref CPI bugs. TipsReference itself previously carried its own inline FedInvest fetch plus local reimplementations of the T+1 business-day walk and the bond-holiday parser; both were consolidated onto the shared module along with the source switch to Fidelity market prices.)
