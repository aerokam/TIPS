## Why

Real Treasury and TIPS instruments carry different coupons, so two bonds of the same maturity
have different modified duration and different yield-to-maturity. Plotting quoted yields against
maturity shows that scatter; re-plotting against duration does not remove it (the reverted
experiment confirmed this — the long end folds back on itself because low-coupon vintages have
longer duration than newer high-coupon issues, and the nominal side has no instrument with
duration above ~18y to pair against a 24y-duration TIPS).

A **spot (zero-coupon) yield curve** removes the coupon effect by construction: it is the set of
discount rates `z(t)` such that every bond's observed price equals the present value of its own
cash flows discounted at `z`. Fit one smooth `z(t)` to the nominal Treasuries and another to the
TIPS, and:

- every point on each curve is a clean function of horizon `t`, coupon-independent;
- **spot breakeven** `= z_nominal(t) − z_real(t)` is smooth and is a true same-horizon breakeven
  at every `t`, unlike the current closest-maturity-nominal BEI which pairs mismatched instruments;
- forward rates and proper present-value discounting become available for the worked examples in
  other apps.

## Functional form: Svensson

The Fed / Gürkaynak-Sack-Wright standard, same form `fitNSS` already uses. The instantaneous
forward rate:

```
f(t) = β0 + β1·exp(−t/τ1) + β2·(t/τ1)·exp(−t/τ1) + β3·(t/τ2)·exp(−t/τ2)
```

The zero-coupon (spot) yield is the average forward from 0 to `t`:

```
z(t) = β0
     + β1·(1−exp(−t/τ1))/(t/τ1)
     + β2·[(1−exp(−t/τ1))/(t/τ1) − exp(−t/τ1)]
     + β3·[(1−exp(−t/τ2))/(t/τ2) − exp(−t/τ2)]
```

`_nssBasis(t, τ1, τ2)` in `src/app.js` already returns the four bracketed `z(t)` basis terms;
given `τ1, τ2` the four `β` are linear and solved by OLS.

### One change from the current `fitNSS`

`calculateSAO` fits NSS **through yield-to-maturity points** — it treats each bond's YTM as a
point on the curve at that bond's maturity. That is close enough for near-zero-coupon TIPS but
wrong for coupon nominals, where YTM ≠ spot. A spot curve must be fit in **price space**: choose
`β, τ` so that, for each bond, `Σ cf_k · exp(−z(t_k)·t_k)` (or the semi-annual discrete equivalent)
matches the observed clean price, minimising price error (or its yield equivalent). Cash-flow
enumeration already exists in `calculateDurationDetail`; factor it into a shared helper.

## Two sources (authoritative + own fit)

Following the repo's authoritative-vs-fallback pattern (`CLAUDE.md` §2a):

### A. Fed published parameters — authoritative reference

The Federal Reserve publishes daily fitted Svensson parameters and the implied curves:

- **Nominal**: Gürkaynak-Sack-Wright (2007), `feds200628.csv`
  (federalreserve.gov/data/nominal-yield-curve.htm).
- **TIPS (real)**: D'Amico-Kim-Wei, from
  federalreserve.gov/data/tips-yield-curve-and-inflation-compensation.htm — the file the user
  downloaded, with `BETA0..BETA3`, `TAU1`, `TAU2`, zero-coupon yields, par yields, forward rates,
  and `BKEVEN*` inflation-compensation columns. *(Confirm exact column names against the download.)*

Consuming these gives the exact published curve — evaluate the formula above client-side at any
horizon. No fitting on our part, no fitting risk.

**Limitations that motivate B:** the Fed series publishes on a ~1-business-day lag, once daily;
and the Fed does **not** seasonally adjust TIPS, so its real curve and its `BKEVEN` still carry
CPI seasonality.

### B. Own fit — the timely, deseasonalized version

Fit the Svensson form to the **live Fidelity feed** (3×/day), fitting the real curve to
**SA-adjusted** TIPS prices (the SA transform from 1.0). This produces:

- a nominal spot curve from current market Treasury prices;
- a **deseasonalized** real spot curve;
- **spot BEI** `= z_nominal(t) − z_real,SA(t)` — smooth, deseasonalized, same-horizon.

**Robustness:** hold `τ1, τ2` at the Fed's latest published values and re-fit only the four `β`
on our prices. With the decays fixed the fit is linear least-squares — the existing
`_nssBasis` + OLS path, no nonlinear optimiser, no local-minima problem. The `τ` evolve slowly,
so anchoring them daily is acceptable; revisit if the residuals show it isn't.

**Cross-check:** a test / visual overlay asserts the own-fit curve tracks the Fed's published
curve within a tolerance (the "verifying redundancy" pattern, not a duplicated implementation).

## What changes in the app

- **X-axis** stays Maturity / Term. A spot curve is already a smooth function of horizon; there
  is no coupon scatter to re-plot away, so no Duration mode.
- **New curve series** on the TIPS and Treasuries yield charts: the fitted spot curve (and
  optionally par yield and instantaneous forward), drawn over the existing scatter of quoted
  yields.
- **BEI tab**: replace closest-maturity-nominal BEI with **spot BEI** `z_nominal(t) − z_real(t)`,
  evaluated on a horizon grid. The Ask / SA / SAO distinction collapses — SA is applied before
  the real-curve fit, and the fitted curve is itself the smoothing that SAO approximates. Decide
  whether to keep the quoted-BEI scatter points underneath.
- **Fed overlay** (optional): show the Fed's published curve alongside the own fit, as a
  reference / sanity check.

## Open decisions

1. **Fit objective** — minimise price error, or yield-of-price error? GSW use a weighted price
   fit with weights ∝ inverse duration (so long bonds don't dominate). Follow that.
2. **Fitting universe** — the app already excludes TIPS < 0.5yr from the NSS fit. GSW/DKW exclude
   the shortest ~18–24 months and (for nominals) on-the-run and first-off-the-run issues. Adopt
   which exclusions?
3. **Own fit: re-fit `β` only (τ anchored to Fed), or full Svensson fit?** Proposal: `β`-only.
4. **BEI**: keep the quoted-BEI scatter under the spot-BEI line, or spot BEI only?
5. **Does the SAO tab/step survive?** If the spot real curve is the fair-value curve, SAO
   (NSS through SA yields) is a near-duplicate. Possibly SAO becomes "read off the spot curve."
6. **Fed data lag** — is a T+1 authoritative overlay useful enough to pipeline, or is the own
   fit + a one-time methodology reference sufficient?

## Terminology (add to DATA_DICTIONARY.md before any user-facing text)

None of these are defined terms yet:

- **spot yield** / **zero-coupon yield** `z(t)` — the rate for a single cash flow at horizon `t`.
- **par yield** — the coupon rate at which a bond of maturity `t` prices at par, given `z`.
- **forward rate** `f(t)` — the instantaneous rate implied for horizon `t`.
- **spot breakeven inflation** — `z_nominal(t) − z_real(t)`; reconcile with the existing
  **BEI** term (the current closest-maturity-nominal construct). One name, one definition.
- **inflation compensation** — the Fed's name for the same quantity; note it embeds an inflation
  risk premium and a TIPS liquidity premium, so it is not pure expected inflation. Same caveat
  applies to any BEI the app shows — this is not a difference between the app and the Fed.
