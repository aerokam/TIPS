## Why

Real Treasury and TIPS instruments carry different coupons, so two bonds of the same maturity
have different modified duration and different yield-to-maturity. Plotting quoted yields against
maturity shows that scatter; re-plotting against duration does not remove it (the reverted
experiment confirmed this — the long end folds back on itself because low-coupon vintages have
longer duration than newer high-coupon issues, and the nominal side has no instrument with
duration above ~18y to pair against a 24y-duration TIPS).

A **spot (zero-coupon) yield curve** removes the coupon effect by construction: it is the set of
discount rates `z(t)` such that every bond's observed price equals the present value of its own
cash flows discounted at `z`. Fit one smooth `z(t)` to the nominal Treasuries and another to the
TIPS, and:

- every point on each curve is a clean function of horizon `t`, coupon-independent;
- **spot breakeven** `= z_nominal(t) − z_real(t)` is smooth and is a true same-horizon breakeven
  at every `t`, unlike the current closest-maturity-nominal BEI which pairs mismatched instruments;
- forward rates and proper present-value discounting become available for the worked examples in
  other apps.

## Functional form: Svensson

The Fed / Gürkaynak-Sack-Wright standard, same form `fitNSS` already uses. The instantaneous
forward rate:

```
f(t) = β0 + β1·exp(−t/τ1) + β2·(t/τ1)·exp(−t/τ1) + β3·(t/τ2)·exp(−t/τ2)
```

The zero-coupon (spot) yield is the average forward from 0 to `t`:

```
z(t) = β0
     + β1·(1−exp(−t/τ1))/(t/τ1)
     + β2·[(1−exp(−t/τ1))/(t/τ1) − exp(−t/τ1)]
     + β3·[(1−exp(−t/τ2))/(t/τ2) − exp(−t/τ2)]
```

`_nssBasis(t, τ1, τ2)` in `src/app.js` already returns the four bracketed `z(t)` basis terms;
given `τ1, τ2` the four `β` are linear and solved by OLS.

### One change from the current `fitNSS`

`calculateSAO` fits NSS **through yield-to-maturity points** — it treats each bond's YTM as a
point on the curve at that bond's maturity. That is close enough for near-zero-coupon TIPS but
wrong for coupon nominals, where YTM ≠ spot. A spot curve must be fit in **price space**: choose
`β, τ` so that, for each bond, `Σ cf_k · exp(−z(t_k)·t_k)` (or the semi-annual discrete equivalent)
matches the observed clean price, minimising price error (or its yield equivalent). Cash-flow
enumeration already exists in `calculateDurationDetail`; factor it into a shared helper.

## What we fit — quoted and SA (and SAO?)

The app currently shows three TIPS series at each bond's maturity: **Ask** (YTM from the quoted
ask price), **SA** (YTM after the seasonal price transform), **SAO** (SA snapped to an
NSS-through-SA-yields curve, with a maturity fade). The spot-curve version keeps that idea but
each series becomes a fitted curve rather than a scatter of per-bond points:

- **Quoted spot curve** `z_ask(t)` — Svensson fit to the quoted ask prices. A smooth curve
  through the raw market; still carries seasonal richness/cheapness as scatter around it.
- **SA spot curve** `z_SA(t)` — Svensson fit to the seasonally adjusted prices (the
  [SA transform](1.0_Seasonal_Adjustments.md), applied to the ask price).
- **SAO** — largely **subsumed**. SAO is defined as "SA read off a smooth NSS curve"; the SA
  spot curve *is* that curve. What SAO adds on top is the **maturity fade** (full snap ≤ 5y,
  fading to raw SA by 6y — see 2.0). Decide whether that fade survives as a blend
  `weight(t)·z_SA(t) + (1−weight(t))·SA_i`, or whether the spot curve simply replaces SAO.

Nominal Treasuries have no seasonal component, so the Treasuries tab gets one curve: `z_nom(t)`.

**The gap between `z_ask(t)` and `z_SA(t)` is itself informative** — it is the seasonal
adjustment's effect, curve-wide, in one picture.

## Spot BEI

`spot BEI(t) = z_nom(t) − z_real(t)`, evaluated on a horizon grid — smooth, and a true
same-horizon breakeven at every `t` (unlike the current closest-maturity-nominal BEI).

- Use `z_SA(t)` for the real yield, so the breakeven is built from seasonally adjusted TIPS
  yields. A `z_ask(t)`-based spot BEI would still carry TIPS seasonality and is probably not
  worth showing.
- The Ask / SA / SAO series on the BEI tab collapse to (at most) two lines: the SA spot BEI,
  and optionally a quoted spot BEI for comparison.

## Own fit — method

`fitSpotNSS` (`src/app.js`, on `main`) fits the Svensson form to each source's quoted TIPS in
**price space**: for each bond, cash flows (`cashflowSchedule`) discounted with `z(t) =
exp(−z·t)` are matched to the observed dirty price, weighted `1/√duration`. It grid-searches
`τ1, τ2` over a coarse list and runs Gauss-Newton on the four (nonlinear) `β` from the YTM-fit
start, keeping the lowest weighted price SSR.

An earlier plan was to hold `τ1, τ2` fixed (from the GSW file) so the fit stays linear
least-squares — worth revisiting if the grid-search + Gauss-Newton proves unstable across
daily updates, but it has held so far. When the SA and nominal fits are added they use the
same `fitSpotNSS`.

## The GSW published curve — external benchmark, not a dependency

The user's downloaded **TIPS spot yields** file is the **Gürkaynak-Sack-Wright** fitted TIPS
curve (FEDS 2008-05, *The TIPS Yield Curve and Inflation Compensation*,
federalreserve.gov/pubs/feds/2008/200805/200805pap.pdf; companion nominal curve is GSW 2007,
FEDS 2006-28). It publishes the fitted `β0..β3, τ1, τ2` plus zero-coupon yields, par yields,
forward rates and TIPS-based inflation compensation. **Published weekly, on Tuesdays, covering
data through the prior Friday** — so it is days-to-a-week stale and not a live data source.

This is **not** the same as **DKW** (D'Amico, Kim, Wei, *Tips from TIPS*) — DKW is a separate
affine term-structure model that *decomposes* inflation compensation into expected inflation, an
inflation risk premium, and a TIPS liquidity premium. Different paper, different authors,
different output. Not relevant to fitting a spot curve.

**How we'd use GSW:** as a validation benchmark (overlay our fit on theirs; a test asserts they
track within tolerance) and as a source of sensible `τ` values. Our method is the same functional
form; the differences are:

| | GSW published curve | Our fit |
|---|---|---|
| Prices | institutional secondary-market close | Fidelity retail ask (or FedInvest mid) |
| Seasonal adjustment | none | the SA spot curve is fitted to seasonally adjusted yields |
| Freshness | weekly, Tue, through prior Fri | 3×/day |
| Universe | all TIPS, excludes shortest ~18–24 mo | our feed, excludes < ~0.5–1y (TBD) |
| Fit target | weighted price fit, full Svensson | price fit, `β`-only with `τ` fixed (proposal) |

Pipelining the GSW file to R2 (`TIPS/GswTipsYieldCurve.csv`,
`Treasuries/GswNominalYieldCurve.csv`, weekly pull) is **optional** — only if the overlay proves
useful. It is not required for the feature.

## Terminology (add to DATA_DICTIONARY.md before any user-facing text)

None of these are defined terms yet:

- **spot yield** / **zero-coupon yield** `z(t)` — the rate for a single cash flow at horizon `t`.
- **par yield** — the coupon rate at which a bond of maturity `t` prices at par, given `z`.
- **forward rate** `f(t)` — the instantaneous rate implied for horizon `t`.
- **spot breakeven inflation** — `z_nom(t) − z_real(t)`; reconcile with the existing **BEI**
  term (the current closest-maturity-nominal construct). One name, one definition.
- **inflation compensation** — GSW's name for the same quantity. It embeds an inflation risk
  premium and a TIPS liquidity premium, so it is not pure expected inflation (this is what DKW
  decomposes). The caveat applies to any breakeven the app shows.
