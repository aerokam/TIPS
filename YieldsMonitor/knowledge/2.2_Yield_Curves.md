# 2.2 Yield Curves Specification

## Dependencies
[2.4_Seasonal_Adjustment.md](./2.4_Seasonal_Adjustment.md) (SA overlay behavior on the TIPS curve).

## Purpose
Visualizes the shift and twist in the yield curves over the active time range.

## Snapshots
Two datasets are plotted for each curve (TIPS and Nominal):
- **Start of Range**: Dashed blue line — every maturity read on the **start date**.
- **Latest / End**: Solid red line — every maturity read on the **end date**.

The start and end **dates** are decided once, from a single anchor symbol, and shared across all three curves (TIPS, Nominal, BEI). The anchor is **10Y TIPS** (`US10YTIPS`) whenever it has data for the active range; if not (CNBC's per-symbol feed reliability can vary by range — see `1.0_Operation.md`'s 1Y/2Y/3Y note), the app falls back through a priority list (`US1YTIPS`, `US30YTIPS`, `US2YTIPS`) rather than leaving every curve blank. The sparse, irregular **5Y TIPS feed must never drive date decisions** (see [`1.0_Operation.md`](./1.0_Operation.md) symbol-reliability note), so it's never in that fallback list. Because `fetchOne()` already clamps the anchor's `rangeData` entry to the active window, its first/last points *are* the start/end dates, and they automatically snap past any non-trading day the user picks.

Each maturity is then read **on those exact dates** via `valueOnDate(sym, dateStr, pickLast)`:
- Start uses the day's first print (the close, for a historical day); End uses the last print on the end day.
- A maturity with **no print on that date is left as a gap** (`null`) — datasets use `spanGaps: false`, so the curve breaks at that maturity rather than borrowing a value from an adjacent date. This is why a flaky 5Y TIPS shows a gap instead of pulling in an out-of-window reading.

## Labeling
Both datasets are labeled with the ET timestamp of the anchor symbol's point that fixed the date (e.g., `06/15 15:00 ET` for the ~3 PM daily close; `04/08 09:30 ET` for intraday). The label is identical across all three curves.

## Custom Date Range
When the **Custom** range is active (see 2.1):
- **Start** = the picked start date. If that day is a non-trading day (no 10Y TIPS print), it snaps **forward** to the next trading day; the label reflects the actual date used.
- **End** = the picked end date, snapping **backward** the same way.
- Snapping is a side effect of anchoring to the window-clamped 10Y TIPS series — no separate calendar logic.

The live-tip merge in `fetchOne()` also enforces the start-date floor on appended intraday points, so a symbol whose stored history has no point inside the window (again, typically 5Y TIPS) cannot leak pre-start bars into `rangeData[sym]`.

## SA Overlay
The sidebar's "Show TIPS yields" toggle (2.4) has two checkboxes, "Quoted" and "SA", both on by default. When "SA" is checked, the **TIPS curve only** gains two additional amber datasets — Start (dashed) and End (solid), same colors/dash convention as the raw curve's blue/red pair — plotted at all five TIPS maturities (1Y/2Y/5Y/10Y/30Y). A maturity/date the rollover log can't resolve (see 2.4's Known limitations) is left `null` on the SA datasets, so the SA line breaks there (`spanGaps: false`) rather than connecting through unresolved points; the End point still resolves whenever the active range's end date is today, since today's bond identity comes from the live CNBC quote rather than the log. When "Quoted" is unchecked, the TIPS curve's own raw Start/End datasets are emptied the same way; the Nominal curve is unaffected by either checkbox (SA is a TIPS-only concept, so it never had a raw-only exception). Both SA datasets are read on the same Start/End dates as the raw curve, via `computeSaSeries()` (the same per-point SA transform used by the Time Series overlay). Dataset slots are always reserved on the TIPS chart (empty/`null` when a checkbox is off) so toggling either updates data in place rather than recreating the chart.
